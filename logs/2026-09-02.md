## 仕組みの理解メモ

### 3点セットの関係
- 自分で書いたもの（コード・Notebook・README）→ GitHub に上げる
- 機械が作るもの（`.venv/` `__pycache__/` `.ipynb_checkpoints/`）→ `.gitignore` で除外
- 除外した環境の再現方法 → `requirements.txt` に書く
- この3つで「誰が clone しても同じ環境で動く」状態になる

### 仮想環境
- `.venv` は「このフォルダ専用の Python 一式」。他プロジェクトとライブラリが混ざらない
- 次回以降は `.\.venv\Scripts\Activate.ps1` で入るだけ。作り直しも pip install も不要
- VSCode で一度カーネルを選べば覚えてくれるので、Notebook 作業だけなら Activate すら不要
- 作り直しが要るのは、`.venv` を消したとき / 別 PC に clone したとき / Python のバージョンを変えたとき
- `pip install` するときはプロンプトに `(.venv)` が付いているか毎回確認する
- 新しいライブラリを入れたら `requirements.txt` にも1行足す（ズレると復元できない）

### git の設定
- `git config user.email` は「コミットに刻む名乗り」。Git は検証しない
- push できるかは「認証（ログイン）」で決まる。名乗りとは別の層
- `--global` なし → このリポの `.git/config` に保存（リポ専用・永続）
- `--global` あり → `~/.gitconfig` に保存（全リポ共通・永続）
- どちらも「今だけ」ではない。ターミナルを閉じても残る
- GitHub に登録したメアドと揃えないと、コミットが草（contribution）に載らない

### Git for Windows とは
- Windows に `git.exe` 本体を入れるインストーラー
- Git Bash は Linux 風シェルのオマケ。PowerShell だけで git は使える
- 同梱の Git Credential Manager が GitHub のブラウザログインを担当している

### Notebook（.ipynb）
- 中身は JSON。`.py` をリネームしても Notebook にはならない
- 変数はカーネルを再起動するまで生き続ける。セルを消しても変数は残る
- `.py` を書き換えても import し直しでは反映されない。Restart Kernel か `%autoreload`
- カーネル再起動：ツールバーの ⟳ Restart、または `Ctrl+Shift+P` → Jupyter: Restart Kernel

### モジュール
- 同じフォルダに `xxx.py` があれば `import xxx` できる（`.py` は付けない）
- 探す順番：実行中ファイルのフォルダ → 標準ライブラリ → `.venv` の site-packages
- import 名と pip 名が違うものがある：`sklearn` → `scikit-learn`、`cv2` → `opencv-python`、`PIL` → `pillow`

## 詰まったこと集

### 1. remote URL に `[200~` が混ざった
- 症状：`git remote -v` の URL の先頭にゴミ文字
- 原因：Git Bash と PowerShell を同時に開いて貼り付けたときの制御文字
- 対処：`git remote set-url origin https://github.com/...` で上書き
- 学び：ターミナルは1つに統一する（PowerShell）

### 2. メアドの末尾に `\n` が入った
- 症状：`.git/config` の email が `...@gmail.com\n`
- 対処：`git config user.email "..."` を打ち直して上書き
- 学び：`git config user.email` で表示して末尾を確認する

### 3. `index.lock` が残って git が動かない
- 症状：`Unable to create '.git/index.lock': File exists`
- 原因：別プロセス（今回は Claude 側の git status）がロックを残した
- 対処：`Remove-Item .git\index.lock`
- 学び：git を同時に動かすものがないか確認してから消す

### 4. push で 403（Permission denied to ichikoji-151）
- 症状：別アカウントとして認証されて拒否
- 原因：PC に保存された別アカウントの認証情報、または VSCode のサインインが横流しされた
- 対処：`git credential-manager erase` で消す → 再ログイン。根本対策は remote URL に `Koichi-1224@` を埋め込む
- 学び：名乗り（config）と認証（ログイン）は別物。github.com への認証は基本1アカウント

### 5. `Password for 'https://...'` と聞かれる
- 症状：ブラウザ認証が出ず、パスワード入力にフォールバック
- 原因：VSCode 統合ターミナルが認証ヘルパーに割り込んだ
- 対処：VSCode 外の PowerShell から push する。または `git.terminalAuthentication` をオフ
- 学び：GitHub はパスワード認証を廃止済み。必ずブラウザ or トークン

### 6. `.py` をリネームして `.ipynb` にしたら開けない
- 原因：`.ipynb` は JSON 形式。中身がコードのままでは Notebook として認識されない
- 対処：`Ctrl+Shift+P` → Create: New Jupyter Notebook で作り直してコードを貼る

### 7. カーネル一覧に `.venv` が出ない → `.venv-1` が生えた
- 原因：VSCode が `.venv` を検出できておらず、「Create Python Environment」を押して別の venv が作られた
- 対処：`.venv-1` を削除。`Python: Select Interpreter` で `.venv`（Workspace）を選ぶと Notebook 側にも出る
- 学び：Notebook のカーネル候補は「Select Interpreter」で登録済みの環境から拾われる

### 8. Notebook が固まる・Interrupt が終わらない
- 症状：簡単なセルが終わらない、`Interrupting...` のまま
- 原因1：`input()` が入力待ちで止まっていた（入力欄は VSCode 上部に出る）
- 原因2：Microsoft Store 版 Python で作った venv はカーネルが固まることがある
- 対処：Store 版をやめて `Programs\Python\Python312` の通常版で venv を作り直し
- 学び：Notebook では `input()` を使わず値を直書きする。venv は公式インストーラー版で作る

### 9. push したのに `basic/` が GitHub に出ない
- 原因：`git commit -am` は新規ファイルを含まない（追跡済みファイルの変更だけ）
- 対処：`git add basic` → commit → push
- 学び：`git add .` → `git commit -m` の2段で行く

### 10. `ModuleNotFoundError`
- `No module named 'numpy'` → venv に入っていない。`pip install numpy` して requirements.txt に追記、カーネル再起動
- `No module named 'sklearn.liner_model'` → sklearn 自体は見つかっている。サブモジュール名のタイポ（linear）
- 学び：エラーのモジュール名が「トップ」で止まるか「サブ」まで出るかで、未インストールか綴りかを見分ける

### 11. 小ネタ
- `volume =` で改行するとエラー。式は1行、または括弧の中でだけ改行できる
- `int(3.9)` は `3`（切り捨て）。四捨五入は `round()`
- `git add.` はスペース抜け。`git add .`
